How it works

Five short chapters, one shared twelve-node mini-town, the same search code that just raced across Canberra. Nothing below is simulated for effect — press play and it's the real algorithm, just small enough to watch by hand.

What Dijkstra actually does

Dijkstra never guesses. It settles the closest unvisited intersection, over and over, always in order of distance from the start — which is exactly why it always finds the true shortest route. The catch: it has no way to know which nodes matter before it visits them, so it explores in every direction at once, spending real work on streets nowhere near the final path. Press play and watch the frontier bloom outward from A until it reaches L — perfect, and blind.

What to notice: the flood reaches streets nowhere near the route to L — Dijkstra can't skip them without already knowing the answer.

Contraction: remove a node without lying about distances

Contraction Hierarchies gets its speed by deleting nodes from the graph — but only if it can prove nothing breaks. Before removing an intersection, it checks every pair of roads that passed through it: if a detour around the intersection is just as short, that pair gets a free pass, a witness. If not, a shortcut edge is added that quietly encodes the trip through the node that's about to disappear. Click any node below to contract it and watch which neighbour pairs pay the shortcut price and which get away with a witness.

What to notice: a witness means a detour already existed; a dashed shortcut means contracting this node would have broken a shortest path without one.

Order is everything

Contracting nodes one at a time raises an obvious question: which one first? Pick badly — say, the town's busiest hub, early — and every path that used to pass through it now needs a shortcut, so the graph gets denser before it gets simpler. A good heuristic prefers nodes that add few shortcuts and remove many edges, contracting quiet cul-de-sacs long before main junctions. The next commit turns this into a game: contract the same mini-town three ways and watch the shortcut count tell the story.

The hierarchy, revealed

Every contraction order implicitly ranks every intersection — and on a real road network, that ranking isn't random. Bridges, parkways, the handful of roads everything else feeds into: these get contracted last, because deleting them early would demand shortcuts everywhere. High rank, it turns out, is just another word for "load-bearing". The next commit sweeps Canberra's real road network by that exact rank, live, so you can watch the arterial skeleton emerge from the suburb around it.

The query: only ever climb

Once every node has a rank, answering "what's the shortest route from A to B" gets almost boring: search upward from A, search upward from B, and stop when the two searches meet. No shortest path can be missed, because every one of them has a highest-ranked node somewhere along it — a summit — and the two climbs are guaranteed to pass through it from either side. The winning route then unzips: each shortcut expands back into the real streets it silently stood in for. The next commit lifts this mini-town so you can watch both climbs happen, live.
